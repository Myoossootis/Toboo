# 可选正面人脸检测（main，尚未发布）

在原 ArUco 检测之外增加“检测目标 → 正面人脸”。适用于摄像头、本地图片，以及视频的“目标检测”算法。修改目标需要先停止再开始；合成场景继续使用 ArUco，录像 CSRT / 帧差保持原有用途。

检测采用现有 OpenCvSharp / OpenCV 的 Haar 正面人脸级联，模型随构建复制到 `models/face/`，不新增 NuGet 依赖或 GPU 要求。选择这个基线可沿用上一版原生运行库；没有升级到需要额外推理部署的模型。

- 所有人脸画框；绿色粗框是当前最大框，其他框为蓝色。
- 最大框中心用于像素位置、中心误差和原有控制计算。逐帧选最大框，多人交错时目标可能切换；颜色不表示身份。
- 没有人脸时仍有实时画面，中心观测为空，沿用丢失后保持的控制逻辑。
- 画面不镜像。最多缩到 640 像素宽检测，框坐标再还原到输入分辨率。
- 日志算法标为 `haar_face`，不填 ArUco 字典或标记 ID；CSV 的 `box_*` 是最大框，`candidate_count` 是人脸框数，状态为 `face_detected` / `no_face_detected`。

这是正面人脸基线，侧脸、遮挡、暗光、远距离小脸可能漏检，也可能误检。没有身份识别、活体判断或人脸关键点功能。没有新增原始画面保存或上传；硬件输出继续关闭。

运行源码：`dotnet run --project src/PanTiltTracker.Desktop`。选择“USB 摄像头”，选好设备，把“检测目标”切为“正面人脸”，再点击“开始实验”。

当前只推送源代码。待用户明确允许发布时，才制作下一版 Release；若基础运行库保持兼容，可同时制作包含相关 DLL、模型和必要配置的小型覆盖包。不是每次更新都能只替换一个 DLL。

## 验证范围

自动测试覆盖本机模型加载、中文目录、灰度/BGR/BGRA 空场景、输入缓冲不被修改、目标切换、无脸图片的预览和日志标签，并保留原控制与录像回归。模型由 .NET 读取 XML 后从内存交给 OpenCV，避免旧版包装器按 ANSI 传文件路径时，在非中文 Windows 上出错。

另用 scikit-image v0.24.0 的 NASA 公有领域 `astronaut.png` 做独立的正例检查：512×512 单人脸、拼接双人脸与最大框选择、1536×1536 缩放坐标还原，以及桌面帧处理链路的正例绘框均通过。该图片及结果仅放在忽略的本地测试目录，不进入 Git；不代表真实摄像头人脸检测已验收。
