## 当前实物信息与结论

- 用户确认两只舵机均为 YBSG90，目前没有万用表，尚未烧录程序。
- 用户提供的适配器铭牌：MODEL 0530，输入 AC 100–240V、50/60Hz；输出 DC 5V、3A；极性符号为中心正、外壳负。图片未显示输出插头尺寸，不能仅凭铭牌认定为 5521。
- 5V、3A 符合此前双小舵机采购方向。3A 是额定供电能力，不是强制流入每只舵机的电流，也不是已经验证的故障限流值。
- 本机归档的厂商云台参数图 `tmp/hardware-review/ptz4.jpg` 列明：9G 高品质数字舵机工作电压 4.8–6.0V；空载电流 80mA、堵转电流 650mA，均以 4.8V 为测试条件。两只按该规格合计约 1.3A，仅用于容量初估；不是用户两只实物在 5V 下的测量值。实际版本、启动峰值、板卡耗电、线损和适配器带载表现仍待核验。
- 亚博官方 [SG90 教程入口](https://www.yahboom.net/study/SG90-Servo/) 与 [云台控制教程](https://www.yahboom.net/study/wheeled_chassis/14412/) 可作型号资料入口；后者列出 SG90 数字舵机 4.8–6.0V。不同厂家、不同 SG90 版本的电流数据不可混用。
- **电源标称参数匹配，但当前不建议直接接两只舵机通电。先借用万用表验证实际电压和转接线极性。** 没有必要因此改买更低电流电源或增加降压模块。

## 硬件复核结果

| 项目 | 证据与风险 | 首次测试要求 |
| --- | --- | --- |
| 动力输入 | 厂商主说明规定 5–8.4V，舵机电源随输入；不自动降成 5V | 这次固定使用 5V，正负接蓝色动力端子对应丝印 |
| 通信 VCC | STM32 接线注意事项明确 VCC 为 3.3V，接 5V 可能击穿芯片 | 初次通信仅接信号和 GND，VCC 留空；勿把舵机电源接入这里 |
| 极性与插头 | 铭牌中心正只说明适配器标称极性；转接线颜色和端子朝向不能代替测量 | 在最终转接线末端测量正负，断电后接线，裸铜不得散开或相碰 |
| 舵机三针 | 信号、电源、地可能插反或错位 | 按实物 S/+/- 或等效标识逐一核对；常见红为正、棕/黑为地、黄/橙为信号，但最终以实物说明为准 |
| 过流保护 | 历史商品图记录 S1–S8、S9–S16 各组约 2A 保护，尚未实测门限与响应 | 组保护不是单只舵机的热保护；单只约 650mA 堵转可能达不到组保护门限，不能靠它防烧 |
| 机械负载 | 0–180 是接口范围，不能证明装配后的云台能无碰撞运动到端点 | 先卸下相机负载或解除会干涉的连杆，固定舵机本体；不得硬掰轴、带载扫全程或故意堵转 |
| 上电动作 | 未烧录外部 MCU 不等于舵机控制板没有出厂固件或没有 PWM | 最先只给不接舵机、不接 MCU 的板供电；不假定上电、复位、断线时输出关闭 |
| 供电路径 | USB 相机和舵机动力为不同供电路径 | 相机 USB 接 PC；MCU 用其规定电源，与驱动板共地，不把独立 5V 电源与 USB 5V 随意并联 |

厂商电池说明明确禁止 7.4V 电池直接用于 5V 舵机。云台旧树莓派教程中“红线接 7.4V”的接法不能用于当前 YBSG90。不要依据板卡输入上限给当前舵机升压。

## 嵌入式与 PC 参数复核

检查范围：厂商 F103C8T6 UART/I²C 教程、两份 `USER/main.c`、UART 发送函数、I²C 发送函数及地址定义；项目 `firmware/`、`config/tracker.json`、Core 控制器与当前应用输出边界。没有审计所有平台底层库或驱动板内部闭源固件，也没有运行厂商例程。

1. **F103C8T6 例程不能直接用于装好相机的首次测试。** UART 与 I²C 的 main 均从 0 开始，每次加 5，条件为 `i < 180`，即发到 175 后立即发 0，再进入空循环。UART 每条命令后延时 100ms，I²C 成功发送后亦延时 100ms。文档笼统描述 0–180，源码实际为 0–175 再回 0；复位会重新扫角。这既可能撞限位，也不是项目配置中的 30°/s 限速。
2. UART 例程的发送函数未检查编号和角度范围；I²C 例程在 NACK 时直接返回、未先发送 STOP，main 也未检查返回值。这些是教学样例，尚不具备项目要求的故障处理与独立超时逻辑。
3. 厂商 UART 为 9600，`$A090#` 表示 S1 的 90 度命令，`$B090#` 表示 S2；**此处仅解释协议，不是现在让用户发送。** 厂商 I²C 7 位地址为 0x2D，位操作发送的写地址字节为 0x5A。不能照搬树莓派旧教程的其他地址，也不能忽视所用 I²C API 的地址约定。
4. PC→MCU（现选 ESP32-S3）的 `SET,...` 是项目草案，与上述厂商协议不同，当前均未接入实际控制链路。PC 应用只计算/记录角度，停止按钮不是舵机动力急停。
5. 配置中的 90° 初值、水平 60–120°、俯仰 70–110°、方向 +1、增益 80、限速 30°/s 均为模拟初值，不能当作实物安全范围。限速约束后续命令变化，也不能保证未知起始轴位到首条命令的运动速度。
6. Core 对缺失/陈旧帧保持命令，不积累大的时间跳变；这不是独立硬件保护。0.5 秒失联保持仍是 MCU 待实现、待独立测试的要求。**保持位置不等于断电；如果已经堵转，保持仍可能继续发热。** 异常应由人立即切断舵机动力电源，并防止俯仰机构失力跌落。

## 借到万用表后的分阶段顺序

1. **电源单独测量。** 两只舵机、控制板均不连接。万用表黑笔插 COM、红笔插 V/Ω，选直流电压档，在转接线最终输出端测接近 5V 且极性正确。不得用电流档直接跨接电源，也不要短接相邻触点。不拆适配器外壳，不接触市电侧。
2. **只给空板供电。** 先断电，把测出的正负线接到蓝色动力端子。板放在绝缘表面，不接 MCU、两只舵机和其他外设，再通电。确认无异常温升或异味，测动力端和舵机供电排针的电压与极性。电源/3.3V 指示灯亮不代表输出已经测量合格。若电压偏离 5V 明显、波动或指示灯反复重启，停下排查。
3. **准备单轴控制，再接第一只舵机。** 确认实际 MCU 板型和电平；先在不接舵机时验证启动、复位、命令限位与失联行为。不要直接烧录全角度扫描样例。断电接一只机械上无干涉的舵机，另一只保持断开。控制从型号规定的中位命令开始；90° 是命令中位，不是装配后的朝向保证，首次到中位仍可能有较大运动。
4. **单只小幅测试。** 以已确认无干涉的中位为基准，逐条变化约 2–5°，每次观察后再发下一条。90→92→90→88→90 仅是在中位已安全确认后的例子。出现顶住不动、持续强烈嗡鸣/抖动、快速发热、异味或板重启，立即断动力，不等待保护动作。
5. **另一只重复，再测两只。** 断电换轴，第二只单独通过后才同时接入；先分别动作，再小幅同时动作，观察板端掉压和复位。普通万用表只能发现较慢的变化，读数正常不能证明不存在快速瞬态。这里不安排故意堵转测试。
6. **最后装载与闭环。** 中位定位后按安装说明装舵盘和相机，留 USB 线松弛量，记录方向与机械安全边界。独立超时测试、限位和单轴试验通过后再进入视觉闭环。

本次尚缺：适配器实测输出与极性、驱动板实物版本及接线确认、实际 MCU 型号、板载启动输出行为、两只舵机带载电流与温升、机械安全范围。当前只完成资料复核，不填写任何虚构的通过数据。

## 2026-11-07 实物检查进展

- 用户已找到万用表，实物照片为 DT9205A；按直流 20V 档指导测量。
- 用户报告：在适配器输出红黑线末端，红表笔接红线、黑表笔接黑线，读数 **+5.23V，稳定**。本步骤要求输出与控制板断开，因此记录为用户报告的空载测量；确认此次接线对应红正、黑负，不按线色单独推定极性。
- 用户随后报告蓝色动力端子处 **+5.19V**；现场照片显示 POWER、3.3V 指示灯亮，舵机输出插针和通信接口未连接负载。记录为空板供电检查，不据照片推断电流、温度或 PWM 状态。
- 用户按步骤测量左侧 S8 通道中间红色供电针相对蓝色动力端子负极，报告 **5.19V**。记录为舵机供电正轨对动力负极的空载读数；没有单独测量 S8 黑色地针，也未测另一组输出或舵机带载表现。
- 用户明确反馈 USB 已接、5V 电源已拔掉后，独立 S1 实际 UART 输出固件 0.2.0 已烧录并通过 MCU 裸板控制测试；最后复位到 DISARMED、参考未知，串口关闭。当前固件具备 GPIO17 输出能力，不再是原永久无输出台架版；详见 [单舵机记录](16-single-servo-bringup.md)。
- 至此有电源/空板/左组供电正轨读数及裸板固件验证。下一步断电连接 MCU 的 TX/GND、核对接线和首只舵机机械空间，再安排实际动作。尚未验证驱动板接收、舵机带载、真实机械边界或动力断电恢复；不作为整机上电验收。
