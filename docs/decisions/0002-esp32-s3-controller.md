## 选型理由

1. ESP32-S3 具备多个硬件 UART，可把 PC 下载/通信端与舵机板 UART 分开。开发板的 USB 桥接下载路线便于首次调试，正常不需要额外 ST-Link。
2. 采用 3.3V GPIO，与厂商给出的 STM32 3.3V 通信路线一致；实际板卡连接仍须核对。ESP32 GPIO 不连接 5V 电源或未经确认的 5V 信号。
3. 照片中的长板引脚、按钮和接口较易接近，适合桌面调试。中间小板也可能足够胜任，但型号不确定；选 S3 不意味着 C3 性能不够。
4. UNO R3 性能足以做双轴控制，但其 5V I/O 和 PC 共用的 D0/D1 硬件串口增加接口安排工作。可改用 I²C 或另行设计串口/电平适配，作为备选即可。**通信 VCC 为 3.3V 并不能单独证明驱动板所有信号脚均不耐 5V**；不把 UNO 判作绝对不兼容。
5. 图像与 YOLO/OpenCV 推理仍在 Windows PC 上完成。S3 只负责命令检查、限位、限速、独立超时与转发，第一阶段不启用无线通信。

## 采用的连接路线

```text
USB 摄像头 ──USB──> PC（C# 视觉与控制）
                         │ USB 数据线 / COM
                         ▼
                  ESP32-S3（台架固件，无运动输出）
                         │ 独立 UART，9600 baud，3.3V 信号
                         ▼
                  16 路舵机控制板 ──PWM──> 两只 YBSG90
                         ▲
                  5V / 3A 适配器动力供电
```

- ESP32-S3 初期只由电脑 USB 供电。外置 5V 接驱动板蓝色动力端子，不给 ESP32 GPIO 或通信口 VCC 供电，不并联电脑 USB 5V。
- 按新增 YD 接口图，正面朝上、天线在上时，选择下方右侧 USB 转串口口做下载和 PC 通信；首次裸板枚举再核对设备与实物布局。一次只接一根 USB 数据线。
- 驱动板初版只需 MCU TX→板 RX，加公共 GND。暂不连接驱动板 TX，不依赖未经证实的角度/到位回读；通信 VCC 留空。双向通信如有需要，先确认返回协议与输出电平。
- 采用独立 UART1，规划 GPIO17/TX→舵机板 RX，GPIO18/RX 预留不接；这两脚已在商家原理图中核对为引出脚。实际接线仍需按丝印确认、通过供电检查并完成无执行器固件验证；不要使用下载串口、USB、启动绑带或存储器占用引脚来控制舵机板。
- 不直接搬用 STM32 的 PA2/PA3 或 PB6/PB7 编号；厂商 UART 协议可以复用，STM32 HAL、寄存器代码和二进制不能烧入 ESP32。

## 固件及验收策略

已用 Arduino CLI 1.5.1 / Arduino-ESP32 3.3.12 编译无执行器固件；工具隔离在 tmp/esp32-tools，版本与配置记录在 firmware/toolchain.json。PC 保持 .NET 8 / dotnet，不引入 Visual Studio 或 C++/CLI 依赖。

先裸板确认芯片与 Flash，再做串口心跳/命令回报。默认不发舵机命令，显式启用后才允许单轴小范围测试。命令解析和定时调度不能被串口等待长期阻塞；在不接舵机时独立验证超范围、畸形输入、断线、复位和超时。

运行中拟定连续 0.5 秒无有效命令即取消尚未执行的运动目标，保持最后实际发出的命令，重新通信后需重新启用，不能继续追赶旧目标。MCU 复位后不能声称知道舵机真实轴位；重新启用与首条运动的安全步骤需要单独测试。ACK 仅表示 MCU 接受请求，不能证明控制板执行或舵机到位。

MCU 未发命令/未启用不等于舵机板没有 PWM；驱动板自身启动、复位与失联行为须单独确认。保持命令不等于切断动力，物理断电仍是卡死或快速发热时的处置方式。

无万用表时可先做 ESP32 单独 USB 枚举与不连接执行器的固件开发；动力接线、单/双舵机实验仍遵守 [首次上电复核](../14-first-power-on-review.md)。
