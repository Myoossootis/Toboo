# 硬件接口

视觉与对话可以独立运行。舵机、UNO 传感器、LCD 与语音设备属于独立可选链路，安装桌面程序不会自动烧录或启动运动。

## Uno 表情屏

四针 5V I²C LCD1602 通过 Uno USB 接收本地实时表情。设备页提供端口、连接和已确认内容预览；只有新鲜、连续确认的摄像头结果才发送有效标签。专用固件会让旧表情在最后接收后最多 500ms 过期。接线、构建、上传及协议见 [Uno 表情屏](lcd.md)。便携版内置 .NET 串口支持，无需 Python；与 UNO 传感器固件二选一，端口独占。

## ESP32 舵机链路

在设备页选择 ESP32 串口并连接、读状态；首次使用打开“快速准备”。日常只保留连接、回中心、开始/停止跟随，详细参数默认折叠。预览切换跟随会先释放原会话并复核条件，不需要切到高级工作台手动停开。

`firmware/esp32_single_servo/` 是实际 UART 输出固件，`firmware/esp32_bench/` 是无执行器输出的逻辑台架固件，两者不能混用。协议见 [single-s1](../firmware/protocol-single-s1.md) 和 [bench](../firmware/protocol-v0.md)。

运动范围、方向、电平、电源和初始位置必须根据具体机构核对。源码中的示例范围不是通用安全值。角度代表请求目标；首次请求时实际轴位未知。固件超时会停止发送目标，不能视作切断动力。采集丢帧和串口异常按各自状态处理，不以生成的视觉结果推断真实运动。

便携版随程序提供隔离的串口运行环境，舵机读状态、微调、回中心和跟随无需另装 Python。请完整解压，保留 `runtime/python/` 与 `firmware/tools/`。只读取状态不需要勾选供电确认，也不会启动运动。源码开发者仍按 [固件说明](../firmware/README.md) 准备本地串口环境。

## UNO 传感器遥测

`firmware/uno_sensors/` 使用独立 UNO USB 采集超声波距离和 MMA8452Q 加速度，默认通道禁用。不会替换 ESP32 固件，也不执行舵机控制。构建步骤和引脚见 [固件说明](../firmware/README.md)。

主机握手 `TOBOO?`，设备回应 `TOBOO_SENSOR,1,UNO`。数据行为：

```text
T1,<seq_uint32>,<device_ms_uint32>,<A|D>,<0|1>,<x>,<y>,<z>*<XOR_HEX2>
```

`A` 为整数 mg，`D` 的 x 为整数 mm，y/z 为零；无效样本的三个数值为零且有效位为 0。XOR 覆盖 `T1` 到 z。单通道样本失效不会被其他通道续期，时间回绕按 uint32 正向差处理；记录与回放分别标明数据来源。

当前传感器融合是预览，不直接控制实际舵机。合成故障场景涵盖近物、姿态异常、断流、恢复确认，不构成实物标定结果。
