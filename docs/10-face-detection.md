# 人脸检测：v0.1.3 支持正面与侧面

后续源代码已增加人脸录像/摄像头的连续确认、空间锁定和对准计算框架，见 [人脸对准](17-face-aiming.md)。下文记录 v0.1.3 的已发布行为；单张图片仍取最大框。新增框架没有发布 Release，也未连接自动舵机输出。

v0.1.2 的 Haar 模型只面向正面脸。v0.1.3 在原有人脸选项中改用 **YuNet 2023mar**，选择“检测目标 → 人脸（正面 / 侧面）”。摄像头、图片和录像目标检测模式共用此链路；合成场景、CSRT 和帧差用途不变。

## 实现与边界

- 使用现有 OpenCV 4.10 DNN 在本机 CPU 推理，不新增 NuGet 依赖、GPU 要求或联网调用。
- 模型为 OpenCV Zoo 的固定 2023mar 版本，232589 字节，MIT 许可与 SHA256 见 models/face/README.md。不使用要求较新 OpenCV 引擎的 2026 模型。
- 图像保持比例、最多缩到 640 像素宽，再在右侧/下侧补齐至 32 的倍数。直接用 BGR 输入；不做镜像显示或额外直方图均衡。
- 分类与目标分数合成后使用 0.8 阈值，IoU 0.3 的 NMS 合并重叠候选。所有保留的人脸画框，最大框供应中心观测；多人交错时可能切换目标，不保持人的身份。
- 框裁到有效图像区域再还原到原分辨率。没有人脸时中心为空，沿用原有丢失/旧帧保持逻辑，不放宽控制时限来掩盖运算延迟。
- 日志算法为 `yunet_face`，实验元数据记录模型版本、姿态范围和阈值；字典/标记 ID 为空。CSV 的 box_* 是最大框，candidate_count 是 NMS 后人脸数。

极端姿态、部分头部出画、遮挡、暗光和特殊画质仍可能漏检或误检。没有身份识别、活体检测、关键点输出或内参标定。没有新增原始图像保存、上传或执行器输出。

模型用 .NET 读取字节，再交给 ONNX 内存加载 API，兼容中文目录。旧正面 Haar 文件保留用于历史比较，不会在新模型缺失时静默降级。更新时必须带上 models/face/face_detection_yunet_2023mar.onnx。

## 验证证据

自动测试覆盖灰度/BGR/BGRA、无目标、输入不被修改、中文路径、模型完整性、坐标缩放与裁边、NMS 去重和相邻人脸保留，以及原有桌面与控制回归。

独立正例使用本地忽略目录中的公开样例，不将照片或输出图像提交 Git：

- 原 NASA astronaut.png：单人脸、拼接双人脸、1536×1536 缩放坐标与桌面帧处理链路均通过。
- Wikimedia Commons Side_me.jpg：旧模型把背景区域当成人脸；YuNet 在原图及水平镜像中均检测到实际侧脸，框还原到相应的原图坐标。该检查是同一照片的两个方向，不代表独立摄像头用户的全面验收。图片 SHA256：`e0e8bdd7cb35969234c844b8e82f25ac99542236c77ab0216b045474e954f439`，来源 https://commons.wikimedia.org/wiki/File:Side_me.jpg 。
- Dad_profile.jpg 这张高反差老照片在两个方向仍漏检，已保留为局限案例，来源 https://commons.wikimedia.org/wiki/File:Dad_profile.jpg 。
- OpenCV extra 的公开多人样例用于补充运行检查，没有据此宣称检测准确率。

新增支持不等于用户摄像头的所有侧脸角度都已验证。v0.1.3 提供完整便携包及从 v0.1.2 升级的覆盖包，等待用户实际摄像头测试；旧版 Release 和附件不变。
