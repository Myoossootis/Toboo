# 基于 CMOS 图像传感器的双轴云台目标跟踪与标定

**项目预提案与可行性分析**  
**课程：** EESM 5840 Introduction to Microsensors  
**日期：** 2026 年 10 月 29 日  
**英文题目：** CMOS Vision Based Target Tracking and Calibration with a Two Axis Pan Tilt Platform

## 一 项目摘要

本项目拟搭建一套低成本视觉跟踪系统，采用 USB CMOS 摄像头获取室内目标图像，在电脑端识别模型上的人工标记，通过现有 STM32 开发板和舵机驱动板控制双轴云台，使目标尽量保持在画面中心。研究重点为相机标定、图像位置测量、闭环控制及跟踪误差评价。

基础验收对象为手持飞行器模型或带标记的刚性目标，运动速度和范围可控。真实无人机跟踪作为扩展，不作为基础项目完成的前提。项目接受一定延迟和定位误差，优先保证系统可重复运行，并用实验数据说明性能与局限。

**初步判断：方案可行，难度为中等。** 选用配套 USB 摄像头和组装云台，可减少摄像头接口及机械制作工作。主要工作量集中在通信联调、云台控制、广角镜头标定和实验设计。现阶段尚未进行实物验证，文中性能数值均为拟定目标或厂商标称参数。

## 二 研究目标与课程相关性

### 2.1 研究问题

1. 经相机标定后，能否在受控条件下稳定获取目标在图像中的位置？
2. 简单比例控制能否驱动双轴云台，使缓慢移动的目标保持在画面中央附近？
3. 控制死区、图像分辨率和目标成像大小如何影响抖动、跟踪误差及有效检测率？

### 2.2 与微传感器课程的联系

系统的传感核心为 CMOS 图像传感器，其像素阵列将入射光转换为电信号，再输出图像数据。报告将讨论光照与曝光、图像噪声、空间采样、镜头畸变以及标定误差如何影响目标位置测量，而不只展示摄像头和舵机联动。课程文件允许采用套件外的传感器及组件。[1]

### 2.3 项目范围

基础版本完成单目标、室内、带人工标记的二维图像跟踪，保留电脑作为图像处理主机。首版不要求识别任意飞行器、不估计飞行器完整三维轨迹，也不要求脱离电脑独立运行。相机内参标定与跟踪误差评价为正式工作内容；没有外部角度参考时，不宣称测得精确的云台实际角度。

## 三 系统方案

### 3.1 硬件架构

```text
带标记模型 → 云台上的 USB 摄像头 → 电脑 C# 与 OpenCvSharp
                                          │
                                      USB 串口通信
                                          │
                                     现有 STM32
                                          │ I²C
                                    16 路舵机驱动板
                                          │ PWM
                                    水平与俯仰舵机
                                          │
                                    改变摄像头朝向
```

电脑负责图像采集、标记检测、误差计算、控制量生成及数据记录。STM32 负责接收指令、检查参数、执行角度限位与通信超时处理，并向舵机驱动板发出命令。驱动板使用厂商对应型号的协议，不默认采用 PCA9685 协议。

STM32 具体型号及其电脑通信接口需要核实。若开发板没有可用的板载 USB 转串口或虚拟串口功能，则补充 USB 转 TTL 模块。具备协议资料时，也可将电脑通过 USB 转 TTL 直接连接驱动板 UART，作为减少联调环节的备选；两条控制路径无需同时实现。

### 3.2 已选硬件与采购判断

| 部件 | 拟采用配置 | 当前判断 |
|---|---|---|
| 摄像头与云台 | 亚博二自由度云台套装，含 200 万像素广角 USB 摄像头、两只舵机及安装配件 | 适合受控目标实验，不需重复购买相机或两只舵机 |
| 舵机驱动板 | 亚博 16 路驱动板，支持 I²C 与 UART | 通道数量有富余，但可用于集中接线和命令控制 |
| 供电组件 | 所选驱动板套装中的 7.4V 电池包与充电器 | 已纳入采购方案，完整组合的供电接法待核实 |
| 处理主机 | 现有电脑 | 用于运行 OpenCV，不额外采购树莓派或 FPGA |
| 控制主板 | 已有 STM32 开发板 | 核对电脑通信方式及可用引脚后使用 |

厂商云台资料列出：200 万像素版摄像头对角视场约 148°，配套数据线约 30cm；PC 平台参考帧率包括 240p@120fps、480p@100fps、1080p@30fps。最高帧率不能与最高分辨率同时理解为一个工作模式，实际帧率与延迟须在本机测量。[2][3]

宽视场有助于目标留在画面中，但同样距离下目标占用像素更少，边缘畸变也更明显。首版从 640×480 开始，在固定照明、中央视野内选择能够稳定识别的标记尺寸和实验距离。

### 3.3 供电接法与待补部件

控制板逻辑电源、舵机动力电源和 PWM 信号电平应分别核对。驱动板资料写明舵机电源取自输入电源；云台资料中的舵机参数为 4.8–6.0V，而所选电池包标称为 7.4V。最终随货舵机规格、套组是否包含转换部件、以及厂家对整套接法的说明，尚需统一确认。[2][4]

## 四 实施方法

### 4.1 目标检测

主方案采用打印的 ArUco 标记，固定在模型上，指定目标 ID，提取标记四角并计算中心位置。标记须面向摄像头，尺寸应保证在实际实验距离下有足够的成像像素。[5]

首先在摄像头固定时验证检测，记录不同距离、照明和轻度倾斜下的有效检测率。若初期标记检测不稳定，可用大面积单色色块完成控制链路的联调；正式测试时明确所采用的检测方法及其适用条件。

### 4.2 相机与云台标定

采用棋盘格或 ChArUco 板，从不同位置和倾斜角度采集约 15–25 张有效图像。固定焦距与分辨率，估计相机内参及畸变参数，并使用独立图像检查重投影误差与校正效果。针对广角成像，依据残差分布选择常规畸变模型或鱼眼模型，不能只凭广角宣传参数决定模型。[6]

云台方面，分别测试水平轴和俯仰轴，确定运动正负方向、中位、可用角度及机械边界。从保守的中间范围开始，避免直接把 0° 和 180° 作为可用极限。命令角度仅用于控制，不视为实际轴角测量。

### 4.3 闭环控制

设实际处理画面宽、高为 W、H，目标中心为 (u, v)，参考中心为 (u₀, v₀)，定义归一化偏差：

```text
eₓ = (u - u₀) / W
eᵧ = (v - v₀) / H
```

参考中心默认取当前处理画面的几何中心。去畸变或裁剪后，应重新确定画面尺寸与参考中心。角度控制采用比例项，结合实测更新时间限制转动速度，并加入中心死区、角度限位和目标丢失处理。

先完成水平单轴跟踪，再加入俯仰轴。连续丢失目标或通信超时时停止更新运动指令并保持位置。为便于归因，先固定比例增益和速度上限，再比较有无中心死区时的误差与抖动。

## 五 实验设计与拟定指标

### 5.1 实验安排

| 实验 | 方法 | 记录结果 |
|---|---|---|
| 成像与检测 | 摄像头固定，改变目标距离、成像大小和照明条件 | 有效检测率、误检及饱和或模糊情况 |
| 标定验证 | 独立于标定数据采集验证图像，检查中心和边缘区域 | 重投影误差、畸变校正效果、适用视野 |
| 静态对准 | 在多个固定位置放置目标，重复启动跟踪 | 对准时间、稳态中心偏差、舵机抖动 |
| 动态跟踪 | 在有位置刻度的平面内缓慢移动模型，每种条件至少重复 3 次 | 居中成功率、偏差时间曲线、丢失次数 |
| 控制对照 | 保持增益、限速、照明和路径条件一致，仅改变死区设置 | 抖动与误差的取舍 |
| 丢失与恢复 | 短暂遮挡标记或将其移出可用视野 | 停止更新是否生效、重新检测后的恢复行为 |

手持路径只能近似重复，因此应记录运动范围及试验过程，必要时使用直尺或导向轨迹辅助移动。抽取部分录像帧人工标注目标中心，核对检测位置，避免仅使用算法自身输出证明检测准确。

### 5.2 拟定验收目标

以下数值用于初步设计，不代表已实现性能。首轮实测后若需调整，应在正式 proposal 中说明依据。

| 指标 | 初步目标与定义 |
|---|---|
| 处理与控制更新频率 | 在选定分辨率下稳定达到至少 10 次/秒，记录实际波动 |
| 受控条件有效检测率 | 至少 90%；分母包含整个测试时段的全部处理帧 |
| 静态对准误差 | 稳态窗口内，水平与垂直归一化绝对偏差的均值分别不超过 0.05 |
| 缓慢运动居中成功率 | 至少 80%；有效检测且同时满足 abs(eₓ)≤0.10、abs(eᵧ)≤0.10 的帧占全部处理帧的比例 |
| 丢失与通信超时 | 拟以连续 0.5 秒无有效目标或无有效命令为停止更新条件，实测验证动作 |
| 标定质量 | 报告标定集与独立验证图像的误差及边缘残差，不预先承诺亚像素精度 |

丢失帧不能当作零误差；偏差统计与有效检测率应同时报告。程序处理时间不等于端到端延迟，后者可通过包含目标运动与云台响应的录像辅助估计，并说明录像帧率带来的时间分辨率限制。

## 六 可行性与风险分析

所选系统不需要自行设计图像传感芯片或高速采集接口，电脑可承担视觉处理；对受控室内目标，工程规模与期末项目相符。难点在于各环节的误差和延迟叠加，低精度要求并不能自动消除闭环振荡、线缆拖拽或检测丢失。

| 风险 | 对结果的影响 | 应对方法 |
|---|---|---|
| 目标在广角画面中太小 | 标记识别率下降 | 放大标记、缩短距离，先限定中央视野 |
| 曝光过长或照明变化 | 运动模糊与检测不稳定 | 固定照明和成像设置，记录使用条件 |
| 舵机回差、死区与结构松动 | 对准抖动，实际轴角偏离命令 | 固定底座，保守限速，分别测试两轴 |
| 旧图像或指令排队 | 云台追赶过去位置，可能振荡 | 优先使用最新帧，限制命令积压并记录时间戳 |
| 电源与接口适配未确认 | 无法可靠联调或出现复位 | 先核对实际套组说明、逻辑电平及输出电压 |
| 初期集成进度滞后 | 双轴系统迟迟无法完成 | 保留固定相机检测和单轴闭环作为分阶段成果 |

项目的工作量与价值主要来自可复现的测量和闭环实验。仅运行厂家预览程序或展示舵机转动不足以构成完整结果；应提交标定参数、测试日志、误差曲线和对照实验。
