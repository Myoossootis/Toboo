# toboo 上位机中的 DeepSeek 交互

2026-11-09，路线2已实现。**聊天输入、回复、停止、新建/历史会话、模型选择和陪伴风格均在 toboo 原有三页界面中**；Harness只在后台提供已有模型服务与认证，Trilium不参与调用链路。

```text
toboo 陪伴页/设置页
  → C# ChatViewModel / TobooChatClient
  → 127.0.0.1:37848 独立 toboo 插件
  → Harness ctx.llm（显式模型路由、零工具声明）
  → 已配置的模型服务
```

## 使用

本机已通过 `scripts/install-toboo-harness.ps1` 安装独立插件，并保留了原Trilium插件条目。更新插件后需要从系统托盘完全退出Harness再打开，普通关窗会保留后台。客户端校验桥接1.0.2，未重载的旧版会显示重启提示并禁用发送。

启动 `scripts/start-toboo.ps1`。正常启动会做只读连接检查，不自动发消息或打开摄像头。在“陪伴”页输入文字，Enter发送，Shift+Enter换行；生成中可点“停止回复”。“设置 → 对话与声音”提供独立模型选择、自然/温柔/简洁风格、新建对话和本机专属历史。对话历史不会列出Harness或Trilium的其他会话，选择模型不修改它们的默认模型。

表情摘要默认关闭，可在设置中开启；只有已连续确认、未过期的实时相机结果才可随下一条文字发送。静态图片、录像、未知表情和旧数据不会被当作当前情绪上传，摄像头画面不发送。语音和LCD发送仍待后续接入。

## 已处理的边界

| 问题 | 实现 |
| --- | --- |
| 通用Agent拥有文件、终端和工具能力 | 直接调用模型服务，不创建Agent或通用工作会话；工具输出拒绝，不进入执行链 |
| 串入私人聊天或Trilium笔记 | 单独目录、单独UUID、单独凭据；没有读取其他会话的接口 |
| 模型选择改变其他应用 | 每轮显式传provider/model，保存toboo本机偏好；不调用全局模型选择接口 |
| 断线后的重复发送 | 先持久保存请求ID和完整负载，再发送；桥接持久去重；不确定时仅显式核对或重试同一ID |
| 停止先到、旧停止误伤新回复 | 按请求ID取消；提前取消记录阻止迟到请求；不取消另一个正在运行的ID |
| 记录没落盘就被当作已接受 | 读取排在写入后；回复完成状态也在落盘后发布 |
| 关闭时排队请求继续开始 | 关闭标记、准入复查和队列排空；关闭主窗口优先停止原视觉/云台会话，再关闭聊天 |
| 两个进程相互覆盖记录 | 桥接恢复前先取独占写锁，客户端发送状态也取独占文件锁 |
| 失联/模型异常导致界面一直等 | 500ms增量刷新，15秒RPC全程时限、90秒生成上限、20秒客户端租约；异常只显示受控提示 |
| 原始错误带出密钥 | 模型错误映射为受控代码/提示；密钥不进入UI、发送负载或诊断 |
| 网络重定向/浏览器跨域调用 | 固定IPv4回环、禁代理和重定向、独立认证、拒绝Origin、限定Host/体积/JSON字段 |
| 表情被重试成“当前情绪” | 本机单调时钟检查，服务端准入再次检查摘要年龄；过期摘要省略，正文仍正常处理 |

请求级去重不代表模型服务计费绝对只发生一次：底层Harness/提供方可能有网络重试，已经消耗的token以其记录为准。取消通过AbortSignal请求结束。共享的模型适配与中间件仍属于用户的Harness环境；未来版本须通过能力/协议检查后使用。

模型上下文、分页、记录上限、隐私目录、协议和安装说明详见 `integrations/toboo-harness/README.md`。未新增NuGet或npm依赖，未捆绑模型密钥、Harness安装文件、Trilium数据库或私人聊天。源码安装依赖插件所在仓库路径，本次没有发布便携包。
