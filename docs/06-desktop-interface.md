# 桌面实验台

启动：`dotnet run --project src/PanTiltTracker.Desktop`。Windows x64 / .NET 8，使用 Avalonia 11.3.22，无需 Visual Studio。原命令行程序仍可独立运行。

## 基本操作

1. 左侧“采集设置”选择图像来源（默认合成场景）及检测目标；“控制参数”调整两轴增益、转速上限、死区与方向。
2. 点击“开始实验”，预览、检测状态、偏差与命令角度实时更新；下方“曲线与运行记录”可展开分析。运行中锁定设置；停止后修改，下一次开始生效。
3. “模拟遮挡”隐藏合成目标：立刻保持命令，持续缺失后显示丢失；关闭遮挡后重新检测并限速恢复。
4. 点击“停止”。日志自动写入 artifacts/desktop/ 的独立运行目录；“导出 CSV”可另存副本。
5. “生成标记”保存带白边的 PNG，默认字典 DICT_4X4_50 / ID 7。打印后测量黑色方块的实际尺寸。

图片只处理一帧后完成；视频按标称帧率回放。切换来源时清空上一次画面与指标，避免把旧结果误认为新来源数据。已有日志仍保留在原目录。USB 模式默认请求 640×480 / 30fps；“采集参数”中可调整模式，实际尺寸以收到图像为准。ArUco 和正面人脸均可选择，具体见 [便携版操作](09-portable-camera.md)。

## 指标与边界

- 偏差以画面宽／高归一化；目标丢失时显示“—”，曲线断开，不填零。
- “报告有效比例”以本次全部处理帧为分母；不是准确率，也不代表全部相机采集帧的检测率。CSRT 仍可能报告漂移框，帧差候选未做类别判断。
- 处理更新按实际墙钟统计，运算耗时为检测与控制耗时，都不等于端到端运动延迟。
- 角度是命令，当前无串口发送。没有真实舵机位置反馈。
- 合成相机理想跟随命令，没有模拟真实镜头、USB 延迟、机械回差或扭矩。
- 原始截图、标定及日志不上传；本项目不连接外部服务器。

## 验证

当前完整检查包含 48 项测试，其中 15 项为桌面测试；覆盖 1280×860 与 980×700 布局、采集/控制标签、分析展开/收起、启动／遮挡／恢复／停止／导出、输入提示、人脸选项与日志、视频框选、单图检测及窗口关闭。测试用 Skia 渲染，预览图位于 artifacts/desktop-preview/ 和 artifacts/ui-refactor-preview/。

便携 EXE 另有原生窗口及合成场景自检；上一版摄像头采集已由用户确认可用。无界面测试不替代新版人脸实际摄像头效果与系统文件对话框的验收。

## 无标记视频模式

视频来源可选择 CSRT 或帧差对照；具体操作见 [无人机跟踪基线](08-drone-tracking-baseline.md)。新增 2 个尺寸下的首帧载入、鼠标拖框、连续跟踪与日志测试，以及 1 个留白、反向拖动和小框拒绝测试。它们使用合成录像，不作为无人机精度证据。
