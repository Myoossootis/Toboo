# 架构与算法边界

## 当前可运行链路

```text
simulate：理想投影 → 合成 ArUco 图像 ─┐
image：本地图片 ────────────────────┤
video：文件逐帧回放 ────────────────┼→ ArUco 检测 → TargetObservation
camera：DirectShow → 最新帧缓冲 ───┘                       ↓
                                            PanTiltController
                                                     ↓
                                      TrackingCommand → CSV／预览
```

当前所有角度输出均进入日志。未实现串口发送，也不驱动硬件。模拟模式将命令直接反馈给理想相机，用于软件链路验证。

## 项目边界

- Core：不含平台或视觉库依赖，接收带时间和尺寸的目标中心，产生两轴命令和状态。
- Vision：实际 OpenCV ArUco 检测、标记生成、合成图像和 Mat 所有权交接。
- App：命令行参数、视频／相机读取、处理流程、预览和 CSV。当前以控制台验证算法，后续 UI 可以复用 Core 与 Vision。
- firmware：未来由 STM32 接收 PC 指令，检查限位与独立通信超时，并控制亚博驱动板。

## 视觉约定

字典固定 DICT_4X4_50，默认 ID 7。检测输入为 Gray8、BGR8 或 BGRA8，转换为灰度后检测。未检测到指定 ID 或同一画面出现重复 ID，均输出无效观测。简单图像中心取四角平均，不称为倾斜目标的精确物理中心。

画面左上为原点，u 向右、v 向下；无镜像。偏差 `ex=(u-W/2)/W`、`ey=(v-H/2)/H`。所有偏差均基于当前处理画面。以后添加 Remap 或裁剪时必须同步更新尺寸及参考中心。

## 控制与时间

比例项生成速度，单位为度/秒；速度乘实际更新时间生成角度增量。两轴有独立方向和增益，以及限位、死区和速度上限。

- Waiting：尚未检测到目标。
- Tracking / Centered：目标有效，控制或位于死区。
- Missing / Lost：缺失时立即保持；超过阈值后记为 Lost。
- Stale：帧龄超阈值或时间来自未来，保持。
- TimingGap：两次有效目标更新之间间隔过长，本次保持，下一次重新开始计时。

重复帧号不重复驱动。无帧轮询不缩短两次有效观测的积分时间。仿真时间由帧号/30 得到，录像时间由帧号/标称 FPS 得到；后者不是可变帧率视频的精确 PTS。相机使用单调时钟的 PC 到达时刻，它不包含传感器曝光及设备内部缓冲时间。

## 帧所有权

实时采集与处理使用容量为 1 的 LatestFrameBuffer。Publish 转移 Mat 所有权；新帧替换未处理旧帧时释放旧 Mat；Take 后由消费者释放。锁内完成提取和清空，避免清空掉生产者的新帧。不无限排队，不在图像采集回调内写 PNG。

相机驱动可能阻塞 Read。当前有应用层无帧超时和有限关闭等待，但没有硬实时保证。实物阶段必须在 STM32 独立实现通信看门狗，不能依赖 PC 线程按时执行。

## 后续接口

先做手动小角度通信，再将 TrackingCommand 送到固件。PC→STM32 的项目协议与 STM32→亚博驱动板的厂商协议分开，见 firmware/。不把记录的命令当成实际轴角反馈。
